# 常见问题

面向使用者的集中答疑，覆盖三件事：如何选择综述类型、运行中遇到问题如何处理、以及高频疑问。

本文件的第二节取代了原先散落在 README 中的故障处理内容，并按工作流程步骤重新组织，便于在出错时直接定位到对应环节。错误码的含义与退出码见 `SKILL.md` 的 Reliability 一节。

---

## 一、如何选择综述类型

判定顺序固定：先看用户的显式表述，再看主题的证据形态，最后回落到默认值。技能在运行期自动完成判定，不向用户询问确认。

| 用户表述或主题特征 | 综述类型 | 对应模板 |
|---|---|---|
| 明确要求 systematic review 或 meta-analysis，或提到 PRISMA | 系统综述 Systematic | `templates/template-systematic.md` |
| 明确要求 perspective、rethinking、critical analysis | 批判视角型 Critical | `templates/template-critical.md` |
| 计算机或人工智能主题，方法密集，提到 survey 或 SOTA | 领域前沿型 SOTA | `templates/template-sota.md` |
| 只说综述、review、overview、survey，未指明类型 | 综合叙事型 Narrative | `templates/template-narrative.md` |
| 生物医学或交叉学科主题，未指明类型 | 综合叙事型 Narrative | `templates/template-narrative.md` |

边界情形的取舍原则：

1. 用户显式指定优先于主题推断。
2. 系统综述仅在前两项之一成立时采用，不因主题证据密集而自行升级为系统综述。
3. 交叉学科主题默认采用叙事型；仅当主题以方法为主且目标发表场合为计算机类会议时，才改用领域前沿型。
4. 主题存在活跃争议时，可在叙事型框架内采用批判性论述，无需改判为批判视角型。

各类型的文献量、篇幅与结构差异见 README 第二节，结构规则见 `templates/structure-common.md`。

## 二、故障处理

按工作流程步骤组织。检索阶段的所有失败都会先经过脚本的退避重试，仍不成功的才进入下表。

| 步骤 | 情况 | 处理 |
|---|---|---|
| 3 检索 | 单个数据库失败 | 脚本自动退避重试，次数由 `--max-attempts` 控制，默认四次；仍失败报 RG-400，最后归类为 RG-201 部分失败或 RG-200 全部失败 |
| 3 检索 | 运行中断或需要补采 | 原命令追加 `--resume`，已完成的主题与数据库组合会被跳过，已获文献自动延续，不必从头重跑 |
| 3 检索 | 结果少于 10 条 | 放宽查询词，扩充同义词，增加数据库，或用 `--topics` 拆分为多组短查询 |
| 3 检索 | 单次检索超过 500 条 | 增加限定词收窄 |
| 4 筛选 | 自动排序结果不理想 | 自动排序只是起点，须逐篇阅读摘要后以 `--keep-indices` 重新指定选入集合 |
| 4 筛选 | 选入集合含预印本 | 生物医学、交叉与通用领域直接剔除，零容忍；计算机与人工智能领域允许 arXiv，但须标注 |
| 5 全文 | 全文不可得 | 以摘要为准，摘要足以支撑九字段提取 |
| 7 起草 | 引文无法核实 | 补全真实元数据，无法补全则整条移除，不留占位符 |
| 7 起草 | 参考文献条目字段缺失 | 按 ERROR 行定位到具体条目，从 `selected_papers.json` 对应的数据库记录补全作者、题名、期刊或来源、年份与标识符（DOI、PMID、arXiv 或 URL）；无法补全则整条移除并重跑引文编号 |
| 7 起草 | 子代理产出格式错误 | 废弃该段文字，由主代理重写 |
| 7 起草 | 上下文即将耗尽 | 以子代理方式延续任务，不中断等待 |
| 9 校验 | 校验未通过 | 按 ERROR 行的错误码定位问题，修正后重跑受影响步骤与校验 |

排查建议：任何脚本都支持 `--error-report` 参数，可把当次收集到的问题写成 JSON，便于批量核对。校验失败时，先看错误码属于哪一类，再决定是补文件、改正文还是重跑脚本。

## 三、高频问题

**需要提供 API 密钥吗？**
不需要。缺少密钥时数据库以基础速率工作，只是检索速度较慢。密钥仅从环境变量读取，不写入输出，不进入版本库。

**可以只输出中文吗？**
不可以。技能始终生成中英双语，两版共用同一套引文编号，章节结构与顺序完全一致。

**可以指定文献数量或年份范围吗？**
可以。检索阶段由 `--max_per_db` 与 `--years` 控制，筛选阶段由 `--keep-indices` 或 `--max-papers` 控制。各综述类型的文献量区间见 README 第二节。

**支持图表吗？**
表格为必备项，每篇至少一张。图件为可选项，纯文本管线通常不生成图；系统综述的 PRISMA 流程图以 Mermaid 代码块形式输出到深析文件。

**为什么不以作者名起句？**
学术综述的叙述主体是发现、方法与机制，而不是研究者个人。以某某等人发现起句，会把综述降格为文献罗列。

**为什么末节命名为展望而不是结论？**
综述属于二次研究，使用结论标题会暗示本文报告原始结果。系统综述是唯一例外，PRISMA 要求保留 Conclusions。

**撰写大概需要多久？**
取决于检索规模与文献量，通常在一小时量级。运行期不暂停、不询问确认。

**中断后可以续跑吗？**
可以。检索阶段会写入检查点文件 `search_progress.json`，续跑命令追加 `--resume` 即可；筛选阶段在结果已最新时会自动跳过。

**生成的文献清单与正文引文不一致怎么办？**
两者应完全一致，正文引用的每篇文献都进入清单，清单中的每条也至少被引用一次。若校验报出差异，重跑引文顺序编号脚本，再重新校验。

**参考文献条目的信息必须完整吗？**
必须。每条文献都须带作者、题名、期刊或来源、出版年份，以及持久标识符（DOI、PMID、arXiv 或 URL）；图书、学位论文、专利、网站与数据集按各自类型格式识别，不强制 DOI。校验脚本逐条检查，缺失即报 RG-300，须补全或移除后重新校验。
