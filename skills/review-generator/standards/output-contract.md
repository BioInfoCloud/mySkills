## Folder structure rules

- Output files go in the **working directory** (the project directory from which the user invoked the session).
- Slug format: lowercase, underscore-separated, ASCII-only (strip accents/special chars, replace hyphens/spaces with underscores). E.g., "mRNA-based therapies for COVID-19" → `mrna_based_therapies_for_covid_19`.
- If the directory already exists, archive existing content to `<topic_slug>/archive/v<N>/` (determine N by checking existing v1/, v2/ subdirectories) and create `<topic_slug>/changelog.md` recording what changed.

### 1. Topic folder structure
```

    ├── literature_search.xlsx   # Raw merged search results (same data)
```

Do NOT output inside the review-generator skill directory. Always use the current working directory.

`<topic_name>`: English lowercase, underscore-separated (e.g., `mRNA_cancer_vaccine`, `LLM_safety_survey`).

**Both .md and .docx files are required.** The .md files serve as source files; the .docx files are generated from them using `<skill-root>/scripts/generate_docx.py`.

### 2. Professional terminology and abbreviations

For the Chinese version, **every professional term and abbreviation must have its English full name on first appearance** in the format:

**Chinese term（English full name，Abbreviation）**

Examples:
- 活性氧（reactive oxygen species，ROS）
- 生成式预训练变换模型（generative pre-trained transformer，GPT）
- 图神经网络（Graph Neural Network，GNN）

After first appearance in each section, use the abbreviation directly (no English expansion).

### 3. review_CN.docx (Chinese)
- Font: 宋体 (body and headings, bold for headings); English text within Chinese document uses Times New Roman
- Title: 16pt bold, center-aligned
- H1: 14pt bold, justified (两端对齐), H2: 12pt bold justified, H3: 12pt bold justified
- Body: 12pt, 1.5 line spacing, justified (两端对齐)
- References: 10pt, hanging indent, justified
- Tables: Academic three-line format (三线表) — top thick line, header-bottom thick line, table-bottom thick line. No vertical or interior horizontal rules.
- Length: Chinese word count is naturally determined by English source text (via translation). No separate standard.
- Structure: 标题 → 摘要 → 关键词(5–8个) → [缩写表] → 引言 → 主题章节 → 结论（综合终章） → 参考文献
- **缩写表**: If ≥10 abbreviations used, include between Keywords and Introduction with columns: 缩写, 中文全称, 英文全称

### 4. review_EN.docx (English)
- Font: Times New Roman (all English text). CJK characters (if any, e.g., author names in references) use 宋体 fallback.
- Title: 16pt bold, center-aligned
- H1: 14pt bold justified, H2: 12pt bold justified, H3: 12pt bold justified
- Body: 12pt, 1.5 line spacing, justified
- References: 10pt, hanging indent, justified
- Tables: Academic three-line format (三线表) — same as CN version
- Length: 
  - Comprehensive/Narrative review: ~8,000–12,000 words
  - State-of-the-Art review: ~10,000–15,000 words
  - Systematic review: ~6,000–10,000 words + appendices
  - Critical/Perspective review: ~5,000–8,000 words
  No upper limit — quality and completeness take precedence.
- Structure: Title → Abstract → Keywords (5–8) → [Abbreviations] → Introduction → Thematic sections → Conclusion ((Final Section, Integrated)) → References
- **Abbreviations table**: If ≥10 abbreviations used, include between Keywords and Introduction with columns: Abbreviation, Full Form

### 5. Reference numbering and integrity
- **Chinese and English share one unified reference numbering system.**
- Vancouver format: `[N] Author AB, Author CD, et al. Title. Journal Abbrev. Year;Vol(Issue):Pages. doi:DOI.`
- Numbered in order of first appearance in the text.
- **Internal ascending order**: Within any multi-citation bracket (e.g., `[5,1,3]`), numbers must be sorted ascending — `[1,3,5]`.
- **Every reference in the list MUST be cited at least once in the text.** No orphan references.
- **Every in-text citation [N] MUST have a corresponding entry in the reference list.** No orphan citations.
- **NEVER use placeholder ranges like [21-157].** Every reference number must correspond to a real, individually cited paper.
- **Reference list paragraphs**: Each `[N]` entry must be separated by a blank line (`.md`) so the .docx generator renders them as individual paragraphs. `renumber_citations.py` handles this automatically.
- Reference count:
  - Comprehensive review: 60–150 references
  - SOTA review: 100–250 references
  - Systematic review: 30–200+ references (depends on field)
  - Critical/Perspective review: 40–80 references
- **Preprints**: Excluded for biomedical/cross/general domains. For CS/AI, arXiv allowed but published version preferred. Mark arXiv-only as `[arXiv preprint]`.
- **PMC full-text**: Retrieved for critical papers. A paper qualifies if it meets ANY of these parallel criteria: (1) thematic centrality — key evidence for a review theme, (2) Tier 1 journal — Nature/Science/Cell/NEJM/Lancet/JAMA and flagship sub-journals, (3) landmark or controversy-resolving, (4) quantitative data source requiring exact verification. Claims extracted only from Results/Discussion; background citations to other papers are NOT attributed to the paper. Abstract is sufficient for most papers (~70-80%).

### 6. literature_search.xlsx
| Column | Description | How to obtain |
|--------|------------|---------------|
| Ref# | Reference number matching the docx | Must match actual citation numbers in the review |
| Title | Full article title | From search result or DOI metadata |
| Authors | All authors | From search result or Crossref/PubMed |
| Journal | Journal or conference name | From search result |
| Year | Publication year | From search result |
| Source DB | Which database(s) retrieved this | Manual tracking (PubMed, OpenAlex, Semantic Scholar, etc.) |
| DOI | Digital Object Identifier | From search result or Crossref API |
| PMID | PubMed ID (if applicable) | From PubMed or Crossref API |
| URL | Direct link to paper | DOI URL, arXiv URL, or publisher page |
| Cited By | Citation count | Semantic Scholar, OpenAlex, Dimensions |
| Open Access | OA status | Unpaywall, DOAJ, or publisher's page (OA/Paywalled/Unknown) |
| Abstract | Brief abstract or summary | From search result or database API |

**Important**: The xlsx must contain ONLY references actually cited in the review text. The Ref# column must exactly match the citation numbers in the docx files. Auto-generated by `generate_docx.py --final-xlsx`.

## Quality bar

| Dimension | Minimum standard |
|-----------|-----------------|
| Review type | Correctly classified (Comprehensive/SOTA/Systematic/Critical) per topic characteristics |
| Body length (EN) | Review-type-appropriate target; quality > word count |
| Citation count | Review-type-appropriate range; every reference traceable |
| **Citation integrity** | Every ref cited; every citation has an entry; no placeholder ranges |
| Databases searched | ≥3 for all domains; peer-reviewed sources prioritized; preprints excluded (biomedical/cross/general) |
| Citation format | Vancouver sequential; ≥3 consecutive numbers use range [12-17] |
| Writing style | 述评结合 — every paragraph synthesizes with critical comparison. No paper-serializing. No raw LaTeX. No internal markers in final text. |
| Verification | Every citation verifiable by DOI/PMID |
| Bilingual consistency | Shared reference numbering; matching section structure; glossary maintained |
| Chinese acronyms | Every abbreviation gets English full name on first use per section |
| Figures and tables | ≥1 comparison table (figures optional — see SKILL.md §7.8). Method comparison tables and technology evolution timelines auto-generated when topic supports them. |
| **Deep analysis** | Mandatory between screening and drafting. 9-field single-paper extraction, 5-dimension clustering, horizontal comparison tables, grounded research gaps. |
| **Search traceability** | Full query log, per-database results count. PRISMA flow diagram for systematic reviews. |
| **Literature structure ratio** | Frontier (past 3-5 yr) ≥60%, foundational 10–20%, rest contextual. |
| **Preprint proportion** | 0% for biomedical/cross/general. <5% for CS/AI; all marked. |
| Font (CN) | 宋体（正文和标题统一）；中文文档中的英文使用Times New Roman |
| Font (EN) | Times New Roman |
| Output formats | Both .md and .docx for each language |
| Output location | Working directory (`./<topic_name>/`), not inside skill folder |

## Missing information handling

If essential information cannot be obtained (unverifiable citation, missing data, unclear finding):
- Do not invent it.
- Insert: `[AUTHOR_INPUT_NEEDED: description of what is missing]`
- Collect all such placeholders in a notes section appended to the output.

## Output notes

Alongside the deliverables, provide a brief summary:
- Domain detected and review type selected
- Databases searched and query groups used
- Total references collected vs. used, with structure ratio (frontier/foundational/contextual)
- Preprint count and justification (if any used)
- Deep analysis summary: number of clusters formed, key comparison dimensions, major gaps identified
- Number of figures and comparison tables generated
- Any AUTHOR_INPUT_NEEDED items
- Key structural choices made (organizational pattern, thesis statement, why)
- Proactive quality assessment results (any issues found and how resolved)
- Self-audit results from writing-quality.md §9

## Script commands

### generate_docx.py
```powershell
python <skill-root>/scripts/generate_docx.py --input-dir "./<topic_slug>" --final-xlsx
```
Generates review_EN.docx, review_CN.docx, literature_search.xlsx (only cited references), and selected_papers.xlsx. Requires review_EN.md, review_CN.md, and selected_papers.json to exist.

### validate_review.py
```powershell
python <skill-root>/scripts/validate_review.py --input-dir "./<topic_slug>" --verify-renumbering
```
Validates structural completeness, reference integrity, and citation numbering. Must print `Review validation passed`.

## Validation workflow (Steps A-D)

Before reporting completion, execute this hard gate:

**Step A — Structural validation**: Run `python <skill-root>/scripts/validate_review.py --input-dir "./<topic_slug>" --verify-renumbering --skip-docx-check --skip-final-xlsx-check`

Common fixes for validation failures:
- Renumbering not done: re-run `python <skill-root>/scripts/renumber_citations.py --input-dir "./<topic_slug>"`
- Missing files: create per this output contract
- Abstract contains `[N]`: remove citations from abstract
- Double brackets `[[` remaining: re-run `python <skill-root>/scripts/renumber_citations.py --input-dir "./<topic_slug>"`
- Prohibited content (preprint mentions, database methodology): delete containing paragraphs

**Step B — Bilingual integrity check**:
- Chinese citation count must match English exactly
- Chinese section headings match English hierarchy exactly
- Chinese abbreviation compliance: `中文全称（English full name，缩写）` per zh.md
- Chinese reference list format: each `[N]` on its own line
- Reference list: identical between languages
- Abstracts: zero `[` in either language
- Reference count: ≥60 (comprehensive), ≥80 (SOTA), ≥40 (critical)
- Scan for `[AUTHOR_INPUT_NEEDED]`, `METADATA_MISSING`, preprint sources, HTML entities

If review_EN.md or review_CN.md content was modified, re-run `python <skill-root>/scripts/renumber_citations.py --input-dir "./<topic_slug>"` before Step C.

**Step C — Regenerate .docx + .xlsx files**:
```powershell
python <skill-root>/scripts/generate_docx.py --input-dir "./<topic_slug>" --final-xlsx
```
Auto-generates: review_EN.docx, review_CN.docx, literature_search.xlsx, selected_papers.xlsx

**Step D — Final validation re-run**:
```powershell
python <skill-root>/scripts/validate_review.py --input-dir "./<topic_slug>" --verify-renumbering
```

Must print `Review validation passed`. Only then report completion.
