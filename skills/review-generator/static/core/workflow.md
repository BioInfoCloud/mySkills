# Review generation workflow

1. Agree the question, audience, date range, citation style, and target length with the user.
2. **Search**: Translate the question into two to five focused search queries. For each query group, build precise search strings with MeSH terms (biomedical), synonyms, and qualifiers. Search all domain-appropriate databases with `scripts/multi_db_search.py` and retain raw JSON outputs plus candidate Excel output for audit. Log all search queries and per-database counts to a search traceability file.
3. **Screen**: Screen titles and abstracts. Select 30–150 papers using tiered priorities: milestone papers, high-impact reviews, recent frontier research (≥60%), supporting studies, and preprints (marked). Exclude low-quality sources, conference abstracts without papers, duplicates, and unverifiable records. Run proactive quality assessment on the candidate set (scope, timeliness, frontier coverage, evidence sufficiency, structure ratio).
4. **Deep analysis (mandatory)**: Read `references/deep-analysis.md`. Perform single-paper structured extraction (8 fields per paper), batch categorization by 4 dimensions, horizontal comparison analysis per cluster with comparison tables, collective limitation summarization, research gap identification (grounded and actionable), timeliness check, and evidence/analysis separation. Save to `<topic_slug>/analysis_output.md`. If evidence is insufficient (<20 papers), stop and ask user for broader search strategy.
5. **Plan**: Build an outline and citation map before prose. The citation map must be grounded in the deep analysis results — each claim and comparison must trace back to specific papers identified during analysis. Assign one sequential Vancouver number to each selected record; do not change the map independently in the two language versions. Plan where method comparison tables and technology evolution timelines will be placed.
6. **Draft**: Read `references/citation-formats.md` for the exact Vancouver format. Draft the English Markdown file from the evidence map and deep analysis output. Every paragraph must combine evidence with critical comparison (述评结合) — compare strengths, weaknesses, and applicable scenarios across studies. Organize thematic sections using the clustering logic from deep analysis. End with 「Current Bottlenecks and Research Gaps」 then 「Future Perspectives」(two separate sections). The bottlenecks and future sections must be directly derived from the deep analysis findings (collective limitations + research gaps). Auto-generate method comparison tables (Markdown) and corresponding visual figures (via `scientific-schematics` or `scientific-visualization`). Then translate the English draft into Chinese, adapting sentence structure, paragraph flow, and conventions for Chinese academic writing.
7. Generate the two Word files via `scripts/generate_docx.py --final-xlsx`, which also auto-creates `literature_search.xlsx` containing only references that are actually cited in the text (matching citation numbers in the docx). Then run `scripts/validate_review.py`.
8. Report searched databases, candidates found, records used, deep analysis summary (clusters, comparisons, gaps identified), any proactive quality issues identified, key structural choices made, and any evidence gaps.
