# 顺序引用工作流（从临时标记到最终顺序编号）

## 1. 起草阶段：用临时双括号标记

撰写立项依据时，使用**临时标记** `[[ref_no]]`，其中 `ref_no` 是 `selected_papers.json`
中该文献的 `ref_no` 字段。**不要**边写边手写最终 `[1][2][3]` —— 重编号留到最后一步，
可避免章节调整导致的级联重排。

示例（**占位示意，用本项目论断替代**）：`<核心机制>是<疾病/现象>的关键驱动因素 [[3],[5],[12]]。`

## 2. 重编号（强制，不可省略）

正文（含 1.N 小节——机制类写科学假说；工具开发/数据库构建类写开发必要性、对科研意义与实现方式，本类不写科学假说）定稿、所有 `[[ref_no]]` 就位后，运行：

```powershell
python <skill-root>/scripts/renumber_citations.py --input-dir "./<project_slug>"
```

脚本动作：
1. 定位 `主要参考文献 / 参考文献` 标题（任意层级）。
2. 对标题**之前**的正文，按 `[[ref_no]]` **首次出现顺序**映射为 `[1],[2],[3]...`。
3. 合并相邻组，连续 3+ 用区间（如 `[1-5]`）。
4. 用 `selected_papers.json` 重建 Vancouver/中文 参考文献列表，替换该标题之后、
   下一个标题之前的内容（不破坏后续章节）。
5. 通过 DOI/PMID 向 Crossref/PubMed 补全缺失元数据（免密钥）。
6. 清除 `[ANALYSIS]/[EVIDENCE]/[CAUTION...]` 等内部标记。

### 重编号后三项校验（必须全过）

```powershell
# 1. 无残留双括号
Select-String -Path "./<project_slug>/proposal.md" -Pattern '\[\['  # 应为空

# 2. 首个引用是 [1]
Select-String -Path "./<project_slug>/proposal.md" -Pattern '\[[0-9]+[,\-0-9]*\]' | Select-Object -First 1

# 3. 引用编号单调递增、无孤儿（由校验脚本覆盖）
python <skill-root>/scripts/validate_proposal.py --input "./<project_slug>/proposal.md"
```

若正文出现 `[86],[20],[121]` 而非 `[1],[2],[3]`，说明**未运行重编号**，必须运行。

## 3. 引用准确性核验（强制，写摘要前做）

重编号后的完整正文 + 参考文献列表已就绪。逐条核验"每个被引论断确实出自所引文献"：

1. **抽查 8–12 条**跨全文的论断；对每条，打开 `selected_papers.json` 找到对应文献摘要，
   确认该文献确实报道了所归因的发现/数据/方法/观点（尤其定量断言：fold-change、百分比、p 值、基准分）。
2. **不支持则修正**：找真正支持的文献替换编号，或弱化/删除该论断。
3. **增删任何引用后必须重跑** `renumber_citations.py`（首现顺序会变），再重跑三项校验。
4. **括号合并核验**：相邻组须合并为区间（见 citation-formats.md）。
5. **完整性**：每个 `[N]` 有对应条目，每条目至少被引 1 次。

跳过此步是"正文与引用对不上"的根因，禁止省略。
