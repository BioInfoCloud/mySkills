# 标准 8：参考文献与引用（本技能自带，零外部依赖）

立项依据的文献检索、筛选、分析与引用编码**全部在本技能内完成**，不依赖 review-generator。
组件清单（路径相对于本技能根 `<skill-root>`）：

| 用途 | 文件 |
|------|------|
| 多库检索 + 筛选 + 选定 | `scripts/literature_search.py` |
| 六维评分筛选 | `standards/scoring-system.md` |
| 深度分析骨架 | `scripts/analysis_skeleton.py` + `guides/deep-analysis.md` |
| 引用格式 | `standards/citation-formats.md` |
| 顺序编码 | `scripts/renumber_citations.py` + `standards/sequential-citation.md` |
| 检索工作流总览 | `guides/literature-search.md` |

> 若同级目录存在 review-generator，其同名文件可作**可选**参考；但本技能不读取它也能独立完成全部任务。

## 1. 检索与筛选

- 运行 `scripts/literature_search.py`（多库免密钥检索）或 agent 用 WebSearch 手工检索后
  经 `--from-json` 规范化；详见 `guides/literature-search.md`。
- 优先**近 5 年、高影响/权威期刊**；立项依据一般筛选 **30–60 篇**。
- 用户已发表文献直接录入 `selected_papers.json`，标注为用户文献。

## 2. 引用编码流程（强制）

1. 起草立项依据时，用**临时标记** `[[ref_no]]`（取自 `selected_papers.json` 的 `ref_no`），**不**手写最终编号。
2. 正文（含 1.N 小节——机制类为科学假说，工具类为开发必要性/意义）定稿、所有 `[[ref_no]]` 就位后，运行：
   ```powershell
   python <skill-root>/scripts/renumber_citations.py --input-dir "./<project_slug>"
   ```
   生成顺序 `[1][2]…` 并重建 Vancouver/中文 参考文献列表到 `1.(N+1) 主要参考文献`。
3. 引用准确性核验：抽查 8–12 条与原文摘要吻合；增删任何引用后**必须重跑**重编号。

## 3. 格式（Vancouver 顺序 + 中文国标）

- 中文文献：`[N] 作者. 文题[J]. 期刊名, 年份, 卷(期): 起止页码.`
- 英文文献：`[N] Author AB, Author CD, et al. Title. J Abbrev. Year;Vol(Issue):Pages. doi:DOI.`
- 每条参考文献**独立成段**（docx 悬挂缩进）；脚本自动判定中/英格式。
- 正文引用置于论断之后、句号之前：`……已被广泛证实 [[3],[5],[12]].`

## 4. 完整性红线

- 近 5 年文献占比 **≥ 50%**；总数适中（立项依据 30–60）。
- **禁止**占位区间如 `[21-157]`；每个编号对应一篇真实、单独被引的文献。
- 每条参考文献**至少被正文引用 1 次**；每条正文引用**必须有对应条目**（孤儿引用/条目均禁止）。
- 摘要、关键词、标题**零引用**。
- **引用精确性红线（对象↔文献必须一一对应，通用占位示例）**：句中并列列举**多个具体对象**（方法/工具/模型/数据库/数据集/算法/基因/药物/队列）时，**每个对象后紧跟其自己的编号**，
  写法为 `对象A[N]、对象B[N+1]、对象C[N+2]`（对象名/编号为占位示意，实际以 `selected_papers.json` 的 `ref_no` 与真实文献为准，**不得照抄占位名**）；
  **禁止**并列后用一组编号笼统覆盖（如 `（如 对象A、对象B、对象C 等）……[11,13,17]`——对象与编号对不上、无法溯源）。
  详见 `standards/citation-formats.md` §2.1。
- **引用位置红线**：`[N]` 引用**只允许出现在立项依据（1.1–1.N）与"主要参考文献"列表内**；研究内容（2.）、研究方案（3.）、创新点（4.）、技术经济指标、研究基础与工作条件等章节**一律不得出现文献引用**——这些章节以方法细节与论证为主，引用堆积会稀释方案详实度。立项依据结尾的 1.N 小节（领域自适应：机制类=科学假说及其验证与意义；工具类=开发必要性/意义/实现方式）仅引支撑本小节论断的证据，不引未来工作，也不使用 `研究策略：`/`研究意义：` 加粗分段写法。
- **有引用必有列表（硬红线）**：正文只要出现 `[N]` 引用，proposal.md 就必须有"主要参考文献"章节与完整条目。
  校验脚本对"正文有引用但无参考文献章节"直接判失败——绝不允许出现无法溯源的孤立编号。
- **区间连接符兼容**：Word 常把 `[1-3]` 自动更正为 `[1–3]`（en dash）。校验与重编号均已兼容
  hyphen(-)/en dash(–)/em dash(—)；起草时统一写 hyphen 即可，脚本两端都能正确展开为 1、2、3。

## 5. 降级说明

若 `literature_search.py` 因网络不可用，用 agent 的 WebSearch 手工检索并喂入
`--from-json`（见 `guides/literature-search.md` C 节）；引用格式与编号规则仍按
`standards/citation-formats.md`、`standards/sequential-citation.md` 执行，并在交付说明
标注 `[文献检索为代理补充，请核对]`。

- **摘要缺失时的红线处置**：降级检索常缺 `abstract`，而"引用前必须与摘要核实实体名与论断"是硬要求。缺摘要的条目**不得**用于绑定具体实体名或量化论断，只能作背景引用；交付说明须逐条标注 `[该条未获摘要，实体与论断未核验]`。
