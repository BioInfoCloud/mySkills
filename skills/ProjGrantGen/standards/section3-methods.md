# 标准 3：拟采取的研究方案及可行性分析

## 3.1 研究方案（### 3.1 研究方案）

- **可设总纲，再分部分（推荐，非强制）**：3.1 开头可用一段**总体研究方案总纲**，先统揽全局——
  用连贯论述概括本项目的总体技术策略、模块划分与逻辑主线（输入→处理→产出→验证），为后续分部分提供"地图"；
  总纲之后再用"第一部分 / 第二部分 …"或按主题/方法组织的具体方案。**总纲须为论点式/策略式概述，不重复罗列具体步骤**。
- **分部分组织方式灵活（二选一，不强求一一对接）**：
  - **方式 A（推荐，默认）**：按 **"第一部分 / 第二部分 / 第三部分 …"** 对接 2.1 的研究内容（每条（1）（2）（3）对应一个"第一部分"），确保"内容—方案"一一对应、可追溯；
  - **方式 B（允许）**：当研究内容天然按技术模块/方法链组织时，可不严格按 2.1 的（1）（2）（3）拆分，而**按主题或方法主线**设"第一部分/第二部分"（如"数据构建与预处理""模型训练与验证""应用与评测"），只要各分部分与 2.1 研究内容在逻辑上全覆盖、无遗漏即可。
  - 两种方式均要求**全部研究内容在方案中均有落地、可追溯**。
- 每个"第一部分"内：先给**技术路线概述**，并用占位/矢量图标注技术路线图：``[图X-Y 技术路线图（针对研究内容N）]``（建议用本技能 `scripts/generate_route_diagram.py` 生成可编辑 SVG 矢量图，便于后续在 Word 中二次编辑；亦可先占位，由用户配图）。
- **技术路线图须详细设计、可多张**：每个"第一部分"至少一张；流程复杂时可将**总体路线图**与**分步细化图**并用（如一张总体路线图统揽全局，再按研究内容或关键模块各出一张分图）。占位标注应写明该图的层级与范围，例如 `[图3-1 总体技术路线图]`、`[图3-2 <研究内容（1）>技术路线图]`。图中应体现输入、处理、产出、验证的完整链路与关键节点（分子/样本/数据 → 方法与操作 → 结果指标 → 验证方式），使评委仅看图即可把握方案骨架。
- 再展开具体步骤，用 `##### （1）` `##### （2）` 编号。
- **常规实验技术不展开**：如 Western blot、PCR、Transwell、细胞培养、常用统计方法等，一句话带过（"采用 Western blot 检测…水平"），把篇幅留给**特色/关键**实验与逻辑。
- 已完成的预实验明确标注 **【已完成】**，拟开展的标注 **【拟开展】**，便于评委区分基础与计划。

## 3.2 可行性分析（### 3.2 可行性分析）

从三维度论述，明确"为什么这事能做成"：
1. **理论可行**：立项依据已论证的科学合理性。
2. **技术可行**：方法成熟/团队已掌握；预实验已验证关键步骤【已完成】。
3. **条件可行**：平台、仪器、合作单位、样本/数据来源可及（呼应"研究基础与工作条件"）。

## 质量要求

- 技术路线逻辑闭环：输入→处理→产出→验证。
- 不堆砌方法名词；每项方法服务于具体科学问题。
- 体量匹配年限（见 `writing-quality.md`）。
