# 标准 4：本项目的特色与创新之处

本块直接决定"新颖性"评分，是项目质量的关键放大器——但**必须真实、不夸大**。

## 撰写规则

- 列 **2–4 条**，**前半部分写"特色"（项目独特之处、区别于现有工作的差异化点），后半部分写"创新"（方法/理论/应用层面的新贡献）**。模板标题是"特色与创新之处"，不能只写创新不写特色。
- 每条结构：`特色/创新点标题（一句话）` + 1–2 句依据（为什么独特/新、与现有工作的区别）。
- 创新层级应是**科学/技术层面**的，而非"我们第一次做这个样本"这类低水平差异。优先从以下角度凝练：
  - **理论/机制创新**：提出新假说、揭示新关系、建立新模型。
  - **方法/技术创新**：新算法、新平台、新指标、新组合策略。
  - **应用/转化创新**：新场景、新人群、新适应症、新政策结合点。
- 与立项依据、研究内容、关键科学问题**前后呼应**，但不重复——这里是"提炼亮点"，不是复述。
- **"首次/首创/国际领先"用词红线**：**除非有确凿文献证据证明在公开文献中尚无同类工作，否则一律禁止使用"首次""首创""国际领先""颠覆性"等表述**。无法举证时，改用"针对……的不足，本项目将 A 与 B 结合""现有研究较少关注……，本项目从……角度"等可支撑表述。使用"首次"时必须在立项依据中提供文献检索证据。
- 若为用户项目，创新点应能从研究基础/文献对比中**找到支撑**。

## 创新表述 4 原则（核心，任何创新点都须符合）

好的创新表述，本质是 **"在公认的研究基础上，清晰说出你往前走的那一小步"**；既不否定前人工作（避免被评审挑"夸大"），也不模糊自身贡献（避免被评审说"创新性不足"）。核心遵循 4 条原则：

1. **先承认已有，再指出缺口，最后说你的改进**：不要一上来就说"首次提出""填补空白"，而是先铺垫领域共识的进展，再精准点出具体的、未被解决的小缺口，你的创新就是针对这个缺口的解决方案。
2. **创新要"可落地、可验证"，拒绝空泛概念**：每一条创新都要对应一个可量化的效果、或可执行的流程，不能只喊"新范式""新框架"。
   写法示例（**全部为占位示意，一律用本项目的真实流程、真实可量化效果替换，不得照抄**）：
   - 不宜：只写"开创科研新范式""构建全新框架"这类空泛说法。
   - 宜：把创新写成"建立一套包含 环节甲、环节乙、环节丙 的闭环流程，可使某类候选方案的试错成本从 X 万元降至 Y 万元"（环节与量化指标用本项目真实内容替换）。
3. **区分"首创"和"优化/定制/集成"**：绝大多数交叉课题的创新是**领域适配创新、集成创新、方法优化**，这本身就是合格的创新，不用硬蹭"国际首创"。例如面向 <领域A> 场景定制 <工具/方法>，就是典型的"领域适配性创新"，比硬说"首创 <领域A> 的 <工具>"更可信（**占位示例**）。
4. **创新点要和可行性绑定**：每一条创新的背后，都要隐含"我们有基础能做到"。例如你说"领域微调提升注释精度"，就要对应你有前期的标注数据和分析管线；你说"验证实验形成闭环"，就要对应你有成熟的实验平台（**占位示例**）。

**表述禁令（适用于所有章节）**：
- **禁止使用破折号（——）**：需补充说明时用逗号、括号或分句自然过渡，不用"××——××"的破折号连接。
- **禁止箭头式表述（→、-->、---->）**：不写"结果 A→结果 B→结论 C"这类箭头串联，改用自然语言描述因果或流程，例如"在结果 A 的基础上得到结果 B，进而得出结论 C"。
- **禁止自指式元叙述**：不写"本节围绕/本节将/如前所述/综上所述"等对文稿自身结构的指称。
- **禁止"AI 腔"套话**："赋能/助力/闭环/抓手/新范式/随着……快速发展"等空泛表述；创新点尤其不得只喊"新范式/新框架"而无具体所指。

- [ ] 每条含标题+依据
- [ ] 创新点为科学/技术/应用层面，非空泛
- [ ] 无"首次/首创/国际领先"等**无证据**夸大表述（有用须在立项依据举证）
- [ ] 每条创新都符合 4 原则：先承认已有，再指缺口，最后说改进；可落地可验证；区分首创/优化/定制/集成；与可行性绑定
- [ ] 与立项依据/研究内容/关键问题呼应且不重复
